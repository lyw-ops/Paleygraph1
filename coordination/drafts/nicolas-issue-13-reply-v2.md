On your question about late-discovered overlaps: retrospectively I found one documented case, the round-91 example above. The older dispatch records are too sparse to say when the connection was first recognized. [Round-91 closeout](https://github.com/lyw-ops/Paleygraph1/blob/9c734d28e1cf4f8df68482f6deac371058c6a2aa/research/round-91-acceptance.json)

Since then we have measured it prospectively. Before each batch, we saved a dependency comparison of the routes about to launch, with its hash bound in the dispatch manifest. At closeout, we classified every confirmed overlap as recognized, missed or unknown, and recorded whether earlier recognition would have changed which missions ran. Over rounds 132–179 there were 52 batch closeouts covering 142 dispatched calls. They found two shared obligations, and both had already been named as `cand:` statements before dispatch. In both cases the calls would still have run as dispatched. No overlap was classified as missed or unknown. One caveat: the same coordinating agent wrote the before and after reviews, so this measures the coordinator's own consistency, not independent detection.

So for now I'd keep the shared `cand:` reference in the checkpoint. A concrete reason to add `needs:` sooner would be a case where seeing the dependency before dispatch changes which missions we run, and we haven't seen one yet. I can publish the format, checks and data from the Paley repository (`coordination/shared-obligations/`) if they would be useful for the template.
